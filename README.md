# TuneNest - 网易云音乐智能歌单分类

Chrome 浏览器插件，自动分类网易云音乐收藏歌单，按情绪、语种、地区、年代、风格创建新歌单。

## 功能

- **歌单 TXT 备份**：导出当前账号全部自建及收藏歌单，一歌单一文件，支持选择文件夹或下载 ZIP
- **歌单合并 / 移动**：单个或多个来源合入已有目标，支持在线歌单及本插件导出的 TXT
- **整理到已有歌单**：一个来源归档到多个已有分类，支持允许／排除目标、个人规则及逐首确认；不确定的歌曲保留原地
- **歌单内歌曲排序**：按加入时间、平台热度、本人累计／最近一周听歌排行次数重排已有歌曲，支持升降序和预览
- **规则分类**：基于歌曲标签、歌手名、发行时间等元数据自动分类
- **AI 分类**：规则无法判定时，调用 DeepSeek API 进行智能分类
- **自动创建歌单**：一键在网易云创建分类后的新歌单
- **页面内嵌 UI**：悬浮按钮 + 侧边面板，不离开网易云页面即可操作

## 分类维度

| 维度 | 示例 |
|------|------|
| 情绪 | 激情、舒缓、悲伤、浪漫、欢快 |
| 语种 | 华语、英语、日语、韩语、粤语 |
| 地区 | 华语、欧美、日本、韩国 |
| 年代 | 70s、80s、90s、00s、10s、20s |
| 风格 | 流行、摇滚、电子、民谣、嘻哈、古典、ACG、国风等 |

## 加载插件

1. 运行 `npm run dev` 或 `npm run build`
2. 打开 Chrome → `chrome://extensions/`
3. 启用「开发者模式」
4. 点击「加载已解压的扩展程序」，选择 `dist/` 目录
5. 打开 [网易云音乐](https://music.163.com)，右下角会出现悬浮按钮

## 导出所有歌单 TXT

1. 登录网易云音乐，在插件主页选择「导出所有歌单 TXT」。
2. 选择本地文件夹，插件会在其中新建带时间的备份子目录；网页无法选择目录时使用「下载 ZIP」，下载完成后解压即可。
3. 普通歌单保存为「歌单名.txt」。Windows 禁用字符会替换为下划线，同名歌单通过歌单 ID 区分，避免覆盖。
4. 核对导出结果中的失败项及数量差异提示；无法读取的歌单单独列出，不会冒充导出成功。

TXT 使用 UTF-8 编码，开头的注释保存版本、账号、歌单 ID、创建人、导出时间及实际记录数，后续每行是一首歌的 JSON，例如：

```text
{"id":12345,"name":"示例歌曲","artists":["示例歌手"],"album":"示例专辑","durationMs":180000,"detailsAvailable":true}
```

歌曲 ID 是合并和去重依据，不按歌名猜测是否同一首歌。歌名中的换行、引号等以 JSON 转义保存。缺少详情时仍保存 ID，详情字段留空并标记为不可用。导出的是歌曲清单，不包含音频，也不是可自动恢复全部歌单状态的完整备份。

歌单统计总数可能与实际返回的 ID 数不同，文件只包含本次实际读取到的歌曲；界面会列出差异。重新导入时请保留原文件的首部和行数信息，截断、无效或重复 ID 的文件会被拒绝。

## 歌单合并 / 移动

1. 在插件主页选择「歌单合并 / 移动」。
2. 在「选择在线歌单」中勾选一个或多个本人创建的来源，再选择一个不同的自建目标歌单。在线操作无需先导出。
3. 也可切换「导入 TXT 备份」，选择一个或多个本插件导出的 TXT；ZIP 需先解压，同一来源一次只导入一份备份。
4. 在线来源默认勾选「移动」；TXT 默认仅复制。取消「移动」时，来源歌曲保留。TXT 移动要求备份账号、歌单创建人和当前登录账号一致，并重新读取对应在线来源，只移除备份中仍存在于来源的歌曲，保留备份后新增的歌曲。
5. 点击「预览本次合并」，核对来源、目标及新增、移除数量，再点击确认执行。来源歌单本身始终保留。

合并按歌曲 ID 去重，只向目标添加缺少的歌曲，保留目标原有歌曲及相对顺序。逐批补入并核验后，仅移除已确认存在于目标的来源歌曲，每批最多 100 首；单首添加或移除失败会跳过并在结束后列出，未完成的歌留在来源，其他歌曲和来源继续处理。

执行期间请勿在其他页面或客户端同时修改相关歌单。网易云没有跨歌单事务；明确的下架、版权等单曲拒绝会回读实际变化，必要时拆分批次定位，已确认成功的 ID 不会重复提交。账号或权限异常、风控、未知请求结果、内容与预期不符等情况停止后续写入，重新读取并报告可核验的结果，读取失败显示未知。已加入目标的歌曲保留，不自动回滚。需要继续时重新预览，来源、目标选择和已导入文件仍保留。

歌单对比清理同样跳过明确的单曲移除失败，继续后续批次，结束后列出失败 ID 和原因；失败歌曲仍留在 A，B 始终只读。原分类功能的创建／追加也使用此处理方式；替换改为先补齐并核验新歌，再移除不再需要的旧歌。任何新歌未加入时保留全部旧歌，报告替换未完成，继续处理其他分类歌单。创建结果未知时不自动重建同名歌单。

开发验证可使用 Node.js 22 执行 `npm run test:playlists`，测试通过模拟网络校验导出、合并、已有歌单归档及原有对比清理，不会修改真实账号歌单。

## 整理到已有歌单

1. 在插件主页选择「整理到已有歌单」，选择本人创建的来源，例如「未分类」。
2. 选择目标范围的模式：「选择允许的歌单」只向勾选的歌单归档；「选择不允许的歌单」将勾选项排除，其他自建歌单均可作为目标。两种模式分别记住勾选结果，来源和收藏歌单始终不能作为目标。排除模式首次默认排除「最近」「未分类」「喜欢的音乐」等收纳歌单，可自行调整。
3. 可在「个人归档规则」中添加明确规则，例如“歌手完全匹配：董真 → 贞惜有你”。支持歌手／专辑完全匹配，以及歌名或专辑包含字面关键词；允许对一首歌匹配多个目标。被排除的目标不会因规则或历史选择被重新启用。范围和规则保存在本机，按登录账号隔离。
4. 点击「分析并预览归档建议」。相同歌曲 ID 已在目标、明确作品／歌手依据、个人规则及已确认的同 ID 去向继续默认多选。其余候选按作品、专辑、歌手历史归类的样本数量和集中程度排序，显示推荐分及选择原因；仅在样本充分、首选至少 75 分且领先次选至少 15 分时默认选一个。推荐分是本地规则强度，不代表正确率。接近、样本少、存在同名异 ID 等情况仍保留原地；可手工调整多个去向或点「保留原地」清除选择。
5. 可选「AI 补充未选歌曲的建议」：使用已有 DeepSeek 设置，发送待确认歌曲的歌名、歌手、专辑，以及允许目标的名称和少量样例；每批 10 首，最多支持 200 个目标。AI 可以不给建议，返回的建议始终需要手工勾选，不会改变已有选择。单批失败保留当前选择，继续后续批次并汇总受影响的歌曲；API Key、服务限制等整体不可用时停止继续请求建议，不影响本地规则和手工归档。
6. 核对参与及保留数量，点击「确认归档并从来源移除」。取消「全部选定目标核验成功后，从来源移除」则仅复制。每首歌曲分别核验全部选定目标：任一目标未成功，该歌留在来源；其他成功歌曲继续移除。单首移除失败也保留在来源并继续处理。结束后列出未完成歌曲的名称／ID、失败歌单、操作和原因；核验完成的同 ID 去向保存在本机供下次参考。
7. 执行前自动保存全部勾选，包括明确的「保留原地」。每次执行后需重新分析读取最新歌单，默认恢复未完成歌曲的选择；已移除的歌曲不再显示，已完成的复制不再自动勾选。草稿按账号和来源隔离，刷新页面后也可恢复；修改目标范围会过滤不再允许的去向。取消「重新分析时保留上次勾选」可重新按推荐生成选择。本机存储失败会提示，当前页面内仍保留勾选。

推断依据的最低样本要求：仅同歌手时至少 8 首、覆盖至少 3 张专辑，且至少 80% 的已归类同歌手参考歌曲落在该目标；合作歌曲的每位歌手都需有参考记录。仅同专辑或作品时至少 4 首且集中度至少 75%；歌手与专辑／作品共同支持时可由至少 3 首不同歌曲形成依据。以上还须同时满足推荐分和领先差距要求。同一 ID 出现在多个目标不会重复放大总样本，通用合集不作为专辑依据，缺失详情会降低推断强度。歌手／作品不对应、个人收纳／回忆／心情类及缺乏演唱语种依据的目标只保留待确认推荐，明确规则和手工选择仍可使用。

目标仅补入缺少的 ID，保留原有歌曲及相对顺序，不清空或替换目标；不按同名歌曲合并不同 ID。预览和执行均使用在线歌单，归档无需先导出 TXT。统计数量差异只作提示；缺少详情时仍保留 ID，但不推测作品、语种或风格。

执行前及各批次（含失败拆分批次）会重新核对账号、归属和相关歌单的内容、顺序；来源移除前后核对所有已选目标。明确的单曲失败跳过继续；无法确定写入结果、账号／权限异常或歌单发生额外变化时停止后续写入，仅回读真实状态，不自动重试未知请求或回滚已添加歌曲，无法读取时显示未知。网易云不提供跨歌单事务，执行期间请勿在其他页面或客户端同时修改这些歌单。

## 歌单内歌曲排序

1. 重新加载插件并刷新网易云页面，在插件主页选择「歌单内歌曲排序」，选择本人创建的歌单。收藏他人的歌单不可写入排序。
2. 选择排序依据：「加入歌单的时间」「平台歌曲热度」「本人累计听歌排行次数」「本人最近一周听歌排行次数」、「组合排序：周次数 → 累计次数 → 热度 → 加入时间」或「按已有歌单分类聚拢（适合“最近”）」。
3. 单项排序默认降序：最近加入、热度高或次数多的排在前面，也可改为升序。相同数值保持原相对顺序。
4. 单项排序中，缺少指标的歌曲默认放末尾，保持它们之间的原相对顺序；也可选择「固定原位置，仅重排有数据的歌曲」。未知值不当作 0，歌曲不会被移除。
5. 点击「读取数据并预览排序」，每首歌曲单独显示排序依据：具体加入时间、平台热度或累计／最近一周听歌次数，同时显示原位置与新位置。听歌次数预览还会列出排行返回数、有效次数记录数及与当前歌单的匹配数；未知时区分未上榜、只返回排行分数、未提供次数或次数无效。组合排序还会显示各组数量、每首歌所属分组和实际比较值，可展开查看四项原始指标。预览前 50 首，可继续展开；写入始终覆盖完整歌曲列表。没有可用指标或顺序无需变化时不写入。
6. 点击「确认将此顺序写入歌单」。执行前重新核对账号和完整歌单，提交后回读验证成员和顺序；如网易云页面仍显示旧列表，请刷新查看。改变歌单、规则、方向或缺失处理方式后，必须重新预览。

组合排序固定按以下优先级分成五部分，每首歌只进入第一个指标大于 0 的组，没有可用指标则进入最后一组：

1. 最近一周次数大于 0：按周次数从高到低。
2. 周次数为 0 或未知、累计次数大于 0：按累计次数从高到低。
3. 前两项为 0 或未知、平台热度大于 0：按热度从高到低。
4. 前三项为 0 或未知、加入时间已知：按加入时间从新到旧。
5. 没有可用指标：保持原相对顺序，排在最后。

组合排序中，0 次、热度 0 和未知具有相同的分组效果，均继续使用下一指标；原始数据仍如实显示为 0 或未知。同组数值相同的歌曲保持原相对顺序。组合模式固定使用上述分组和方向，不提供单项排序的升序或未知固定位置选项。

分类聚拢排序适合「最近」这类横跨多个分类的歌单：

1. 默认使用账号列表中其他自建及收藏歌单作为分类参考，当前待排序歌单始终排除。勾选决定参与范围，上移／下移决定标记优先级；默认优先级为平台返回的列表显示顺序，不按歌单 ID 大小排序。建议取消「我喜欢」「未分类」等汇总歌单，避免把多数歌曲聚成同一大段。
2. 按歌曲 ID 核对参考歌单中的实际成员，为每首目标歌曲保存按优先级排列的歌单 ID 标记。参考歌单的内部歌曲顺序不影响结果；歌曲详情不可用时仍保留 ID 和可读取的分类标记。
3. 每轮从目标歌单原顺序取第一首未排定歌曲作为本段起点，依次遍历它的歌单标记，将相同标记的未排定歌曲按原相对顺序接到后面。已排定的歌曲不再移动或展开其其他分类；没有标记的歌曲也按轮次保留。
4. 例如 A 属于 U、I，B、C 属于 U，C、D 属于 I，U 优先于 I：即使 D 原先比 B、C 靠前，仍排列为 A、B、C、D，C 只出现一次。下一轮从原列表中找尚未排定的歌曲继续。
5. 预览显示每段的起始歌曲、逐首分类标记（歌单名和 ID）、本次跟随的歌曲及共同分类，并可查看各参考歌单的匹配数量。调整目标、参考范围或优先级后必须重新预览。

分类参考始终只读，分类判断固定为本次预览读取的交集。个别参考歌单不可读或成员数量无法核实时，跳过并在预览列出原因；这不表示歌曲未分类，也不会删掉歌曲。登录失效、限流及明确风控异常会停止预览。没有匹配分类或顺序不变时无需写入；其他情况同样使用完整 ID 排列和写入前后校验。

排序数据口径：

- 加入时间使用平台当前保存的成员加入时间，不把当前显示位置、歌曲发行时间当作加入时间。移除后重新加入可能使用再次加入的时间；平台未保存的历史加入时间无法恢复。
- 热度使用歌曲详情中的平台热度值，通常为 0–100，不是全网播放总次数；同分较多属于正常情况。
- 读取热度时，明确的单曲不可用会拆分定位，该曲保留为未知，其他歌曲继续读取。排序写入必须提交完整成员，不能因单曲报错省略其 ID；整单写入失败仍停止并核验，避免丢歌。
- 个人次数使用当前登录用户的累计或最近一周听歌排行，兼容数字及纯整数字符串形式的次数。平台只返回有限数量的歌曲，未返回的歌曲次数未知，不表示 0 次；只有排行分数但没有次数时也标为未知，不将分数冒充次数。因此这是按平台返回次数排序，无法保证覆盖每首歌的完整累计播放历史。单项次数排序全是未知时保留原顺序；次数相同也保持原相对顺序。
- 组合排序会分别读取周排行、累计排行和歌曲热度；单首歌曲指标为 0 或未知时使用下一项，指标接口整体失败时停止只读预览，不将请求失败当作全体歌曲的数据未知。
- 最近一个月暂不支持，界面已标注不可用。现有排行接口不能提供完整月度次数，不能简单把每周排行相加当作月度统计。

仅使用更新顺序的操作，一次提交当前成员的完整排列，不增删歌曲、不清空再添加、不把列表分批覆盖。平台统计可能包含或不包含云盘歌曲：实际 ID 数等于平台统计数，或恰好等于平台统计数加云盘数时可排序。例如平台统计 260 首、云盘 1 首、实际读取 261 个 ID，预览会说明差异并保留全部 261 首。其他无法解释的数量差异仍拒绝排序。写后按同一规则核验数量，并逐一比对完整成员和顺序；缺失云盘歌曲也不会报告成功，无法确认完整性时标为未知。

执行期间请勿在其他页面或客户端修改此歌单。平台没有附带版本条件的更新接口；外部并发变更只能在检查时发现，不能跨客户端加锁。业务失败、超时、账号或歌单变化时停止，只回读结果，不自动重试或回滚，继续前需重新预览。

接口依据：[歌曲顺序更新](https://github.com/neteasecloudmusicapienhanced/api-enhanced/blob/main/module/song_order_update.js)、[听歌排行时间范围](https://github.com/neteasecloudmusicapienhanced/api-enhanced/blob/main/module/user_record.js)。本地模拟测试覆盖排序及失败场景，不会修改真实账号歌单。
